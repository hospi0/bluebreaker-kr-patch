# 이어하기 — 블루 브레이커 ~검보다도 미소를~ (새턴 JP)

비공개 저장소. ROM·스테이트·디스크에서 뽑은 파일·빌드 결과물은 없다(로컬에만). **클라우드에서는 번역만** 하고 빌드·실기는 로컬에서 한다.
상세 분석은 `docs/01_초기조사.md`.

## 1. 클라우드 번역

### 파일
- 원문: `work/text/scr.tsv`(대사, SCR.BIN — 고유 6,093덩어리 · 약 19.1만 자) · `work/text/sys.tsv`(메뉴·아이템·기술·도움말·지명, 0.BIN 등 — 648줄). **원문 파일은 고치지 말 것.**
- 번역: 원문 파일을 `work/ko/` 에 같은 이름으로 복사해 **«번역» 열만** 채운다(파일을 나누지 말 것 — 진행은 아래 «진행 기록»에 ID 범위로).
- 열: `ID · 위치 · 구분 · 공유 · 원문 · 번역` — 공유 = 같은 원문이 나오는 자리 수(한 번 번역하면 전부에 들어감).
  - scr 의 구분: `대사`(«{」…»» 대사창) · `나레이션`(TC 화면 글).
  - sys 의 구분: `메뉴:NB` = **원래 N바이트 안에 들어가야 한다**(제자리 — 한글 1자 = 2바이트, 반각 가타카나 1자 = 1바이트였던 자리 주의) · `잡음?:NB` = 가나 없는 짧은 조각(대개 표 데이터) — 뜻이 안 되면 비워 둘 것.

### 토큰 (원문과 같은 순서·개수 그대로)
| 표기 | 뜻 |
|---|---|
| `\n` | 줄바꿈(RT) — **원문 자리 그대로**. 대사창은 한 줄 전각 15자 안팎 + 다음 줄 들여쓰기 전각 공백(원문처럼) |
| `{PC}` | 쪽 넘김(버튼 대기) |
| `{MK0}`‥`{MK9}` · `{EP}` · `{TC}` · `{NMR:xxx}` | 표시·변수 명령 — 그대로 |
| `{sp}` | 반각 공백 1칸 |
| `{a:XX}` | 그 밖 바이트 — 그대로 |
| 원문의 반각 ASCII 숫자(EP 비용 등) | 그대로 |

### 문자·말투 규칙
- 번역에 **가나·한자를 남기지 말 것**(한자 칸을 한글로 덮어쓴다).
- 일본어 고유명사는 **거센소리**(か=카 · た=타 · つ=츠). 인물: ケイン→케인 · アーシャ→아샤 · ディーザ→디자 · サージュ→사주 · ターナ→타나 · マヤ→마야 · レッカ→렛카 · ナルター→나르타 · ヤーム→얌 · ラミーユ→라뮤 · カルミー→카르미 · ハミュン→하뮨 (⚠초안 — 사용자 확인 전).
- 문장부호 뒤 공백은 빌더가 지운다(전 프로젝트 규칙).
- 말투는 원문을 살린다(ケイン 반말, 신관·하인 존댓말 등). 같은 인물은 같은 말투로.
- 대사 첫머리 «이름「» 꼴은 그대로(«케인「…»).

### 진행 기록
- 2026-10-01 클라우드: **scr B00001‥B06093 전부 완료** · **sys 547/648 완료**(남은 101줄은 표 데이터·바이너리 잡음 — 비워 둠: S00001·S00275·S00280‥S00283·S00293·S00347(디버그 «ダミーデータ»)·S00406‥S00413·S00564‥S00648).
- 검사기 `tools/ko_merge.py` (`python tools/ko_merge.py --check`): 토큰 순서·개수 = 원문 · 가나/한자/한글 자모 잔류 0 · 한 줄 폭 ≤ 17(전각 1·반각 0.5) · 메뉴:NB 바이트 예산(한글 2B·반각 1B) — 현재 오류 0.

### 번역 메모 (빌더·실기 때 확인할 것)
- **띄어쓰기 = 반각 공백(ASCII 0x20)**. 폭 계산은 0.5칸. 빌더가 전각 공백으로 바꾸면 줄 폭이 넘칠 수 있음(한 줄 최대 17칸 기준으로 맞춤).
- 문장부호는 원문 전각 그대로(、。！？…～「」（）・). 대사창 줄 첫머리 전각 공백 들여쓰기 유지.
- 이름·아이템 변수 뒤 조사는 «을(를)·이(가)·은(는)»로 둠(B00682 등 «を\n　○○に渡す» 계열, B01591·B01594·B01602·B01630·B01631·B04754·B06003, B01665 «(이)야»). 레벨업 «레벨 {NMR:R03}에 올랐다».
- S00301·S00304: 원문 «…設定しま» 다음 줄 «す。»(2자라 추출 안 됨)이 따로 있음 → 그 덩어리를 «다。»로 바꿔야 «설정합니다。»가 됨(둘 다 4B).
- S00285 앞머리 «{a:0A}噺» 는 원문 바이트 그대로 둠(문자열 앞 표 데이터로 보임).
- 기술 설명(S00466‥S00539): 이름 칸은 원문과 같은 바이트까지 전각 공백(홀수면 반각 1개)으로 채움. 대상 표기 敵単/敵全/味単/味全/全体 → 적１/적전/아１/아전/전체.
- 공지판 조각(B02144‥B02151 등)은 원문 줄 나눔 단위로 이어지는 문장 — 앞뒤 조각과 이어 읽히게 나눔. B04090 «において、» → «에서、», B05847 «が…» → «가…»(앞 조각 = «부유 왕국 플로르»).
